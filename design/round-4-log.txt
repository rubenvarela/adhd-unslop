   142	## Lifecycle
   143	
   144	Activation. The skill is active when the user invokes it (`/adhd-unslop` in
   145	Claude Code, `$adhd-unslop` in Codex) or when the always-on hook injects it
   146	at session `startup` or `clear`. Both parts start active. Claude Code blocks
   147	model-initiated Skill calls (`disable-model-invocation: true`). Codex
   148	disables implicit skill selection (`allow_implicit_invocation: false`). The
   149	Codex AGENTS.md fallback explicitly tells the model to read and follow the
   150	complete installed SKILL.md.
   151	
   152	Two modes, ADHD and unslop, each with an independent switch. ("Mode" is
   153	one of the two rule sets. "Chunk" is one of the three hook deliveries.)
   154	Each mode holds its own state for the session:
   155	
   156	- "stop adhd mode" disables ADHD and leaves unslop's current state unchanged.
   157	- "stop unslop" disables unslop and leaves ADHD's current state unchanged.
   158	- "normal mode" disables both.
   159	- Invoking the skill again enables both.
   160	- Confirm each change in one line naming what is now active.
   161	
   162	State rule, in the skill and in every chunk header: restore the latest
   163	known state of each mode in this session. Explicit invocation enables both.
   164	Stop commands change only the named mode. Receiving or reloading these
   165	instructions does not change known state. If no state is known, both modes
   166	are active. Quoted or discussed control phrases are not commands.
   167	
   168	Persistence. Active parts stay active for the rest of the session, across
   169	topic changes. The hook also fires on `resume` and `compact` to restore the
   170	instructions after context loss.
   171	
   172	Known limitation, documented in README. Mode state lives in conversation
   173	context, not durable storage. Compaction or resume can lose it. Reinjection
   174	restores instructions, not lost state, so it may restore the active
   175	defaults and a stop command may need repeating. A file-backed state store
   176	is not built in v1.

   258	### Hook (both runtimes)
   259	
   260	Codex supports plugin `hooks/hooks.json` with `SessionStart` sources
   261	`startup|resume|clear|compact`, sets `PLUGIN_ROOT` and `CLAUDE_PLUGIN_ROOT`,
   262	and requires the user to review and trust the current hook definition in
   263	`/hooks`; a changed definition needs review again because trust is recorded
   264	against the definition's hash (developers.openai.com/codex/hooks). The
   265	upstream i-have-adhd launcher already reads both env vars, so one
   266	`hooks.json` serves both runtimes.
   267	
   268	Output caps. Claude Code caps each returned hook context value at 10,000
   269	characters and replaces larger values with a file path and preview
   270	(code.claude.com/docs/en/hooks). Codex caps each handler at about 2,500
   271	tokens by default and raises it per handler with `additionalContextLimit`.
   272	The build reports the exact emitted size of every chunk; the current
   273	overlay plus stripped upstream bodies already exceed 19,000 characters, so a
   274	single handler cannot deliver the composite on Claude Code.
   275	
   276	Delivery model. Matching handlers run concurrently. All three are
   277	synchronous. Each successful handler contributes its own context value
   278	subject to its own limit. Nothing depends on arrival order or on transcript
   279	message boundaries. One matcher group is not an all-or-nothing contract:
   280	Codex can skip untrusted handlers and disable individual ones, and a timeout
   281	or crash can drop any chunk. Completeness is therefore a model instruction
   282	carried in every chunk, not a runtime guarantee.
   283	
   284	Design: three command handlers under one `SessionStart` matcher group. Each
   285	runs the same launcher with `ADHD_UNSLOP_CHUNK` set to `1`, `2`, or `3`.
   286	The payloads are contiguous slices of the generated composite, in order:
   287	
   288	1. Composite prefix through the end of the lifecycle section.
   289	2. The i-have-adhd block, including its provenance markers.
   290	3. The unslop block, including its markers, and the final check.
   291	
   292	Concatenating the three payloads in index order reproduces the composite
   293	body byte-for-byte. Transport text (header and footer) is separate from the
   294	payload.
   295	
   296	Generated chunk files. `tools/build.mjs` writes `hooks/chunks/1.md`,
   297	`2.md`, `3.md` and `hooks/chunks/manifest.json` holding the composite
   298	sha256, each chunk's sha256, and each chunk's emitted size. The launcher
   299	reads the manifest, validates the selected payload's hash, assembles the
   300	complete value (header, payload, footer, expanded flag paths), checks it
   301	against the size limits, and only then writes stdout. On any mismatch it
   302	prints nothing and exits 0. Tests reconstruct the composite from the
   303	payloads and reject stale generated files.
   304	
   305	Chunk header (identical wording in every chunk, with N and HASH filled in):
   306	
   307	```
   308	ADHD-UNSLOP INSTRUCTIONS. Chunk N of 3 from bundle HASH. Apply this bundle
   309	only once all three chunks with this hash have arrived; if any is missing,
   310	keep any earlier complete configuration, say once which chunk is missing,
   311	and do not activate from the partial set. A repeated chunk with the same
   312	hash and index is a repeat, not a new activation. Do not combine chunks
   313	from different hashes. Receiving instructions does not change established
   314	mode state: restore the latest known state of the ADHD mode and the unslop
   315	mode in this session; if none is known, both are active. Precedence: on a
   316	direct reply ADHD wins a conflict, elsewhere unslop wins.
   317	```
   318	
   319	Chunk footer:
   320	
   321	```
   322	END adhd-unslop chunk N of 3 (HASH). To stop always-on injection remove
   323	every opt-in flag: <expanded flag paths>. "normal mode" turns both modes
   324	off for this session.
   325	```
   326	
   327	Missing or untrusted handlers are not recovered by another route. README
   328	tells the user to trust or enable all three handlers, or to invoke the
   329	skill explicitly instead.
   330	
   331	Codex fallback without hooks: README gives a `~/.codex/AGENTS.md` snippet
   332	that instructs the model to read and follow the complete installed
   333	`SKILL.md` for `adhd-unslop` at the start of every session. The snippet
   334	contains no rules of its own.
   335	
   336	Codex prompt stub (`.codex-plugin/prompts/adhd-unslop.md`) is an optional
   337	slash shortcut. Not shipped in v1; README notes how to add one. Claude Code
   338	users can also type the qualified `/adhd-unslop:adhd-unslop` if another
   339	command occupies the bare name.

   341	### Upgrade flow
   342	
   343	```
   344	node tools/sync.mjs --check                     # upstream/ matches pinned sha256
   345	node tools/sync.mjs --bump i-have-adhd <commit> # fetch at commit, stage, print diff
   346	node tools/build.mjs                            # regenerate composite, stamp versions
   347	node --test tests/                              # invariants
   348	git diff upstream/ skills/ overlay/             # review every change for applicability, conflicts, activation, dependencies
   349	```
   350	
   351	`--bump` fetches SKILL.md and LICENSE from raw.githubusercontent.com at the
   352	commit into a staging directory (`.sync-staging/<name>/`), records a
   353	separate sha256 for each file, builds and tests against the staged pins,
   354	and only then promotes sources, pins, and generated output together. On
   355	failure it keeps staging for inspection and leaves canonical files
   356	unchanged. It warns when the new body adds a rule number or heading the
   357	overlay does not cite, and fails when the overlay cites a rule number that
   358	no longer exists or when the new body references a runtime dependency
   359	(`references/`, `scripts/`, `agents/`, or a relative link) that the
   360	composite does not ship.

1. **Restore the flag specification.**

   V4 mentions “the Claude flag or the Codex flag” but no longer defines either path or how they combine.

   Replace line 239:

   > “reads flag, prints banner + composite body”

   With:

   > “Checks for `.adhd-unslop-always` under `CLAUDE_CONFIG_DIR`, defaulting to `~/.claude`, and under `CODEX_HOME`, defaulting to `~/.codex`. Either flag enables all three handlers in either runtime. With neither flag present, exit 0 without output. Emit only the selected chunk after validation.”

2. **Make completeness explicitly precede activation.**

   Lines 144–146 still say:

   > “when the always-on hook injects it … Both parts start active.”

   That conflicts with the incomplete-bundle rule. Replace with:

   > “Explicit user invocation enables both modes. Hook delivery may initialize mode defaults only after a complete matching bundle is available. An incomplete bundle initializes neither mode. Receiving a complete bundle preserves known mode states; an unknown mode defaults to active.”

   Make the header’s default conditional too. Replace:

   > “if none is known, both are active”

   With:

   > “after a complete bundle is available, default each unknown mode to active”

   Also specify which rules survive an upgrade. Replace:

   > “keep any earlier complete configuration”

   With:

   > “retain the previously selected complete bundle and current mode states. A newly completed bundle replaces its rules without resetting those states. Repeated chunks from an older bundle do not select that bundle again.”

3. **Separate reproducible manifest data from runtime sizes.**

   Lines 297–300 require the manifest to contain:

   > “each chunk’s emitted size”

   But emitted text includes flag paths that differ by machine. Two implementations could produce different committed manifests from identical sources.

   Replace with:

   > “The manifest records SHA-256 hashes over the exact UTF-8 bytes of the composite body and each payload, plus payload byte counts and UTF-16 code-unit counts. Do not normalize payload whitespace or line endings. Environment-dependent emitted sizes are not committed. The launcher measures the complete expanded value at runtime.”

   Replace test 8’s:

   > “the longest plausible flag paths”

   With:

   > “fixed path fixtures with documented lengths, plus an oversized-path case that verifies rejection before any payload output”

   Use one shared, specified token-estimation function in the build, launcher, and tests.

4. **Remove the spill-file shortcut from delivery verification.**

   Lines 404–405 say:

   > “read the session log or the `hook_outputs` spill directory. Compare each value with the chunk file.”

   A spill file contains the full output precisely when the model received a shorter preview. It cannot prove complete delivery. Also, the delivered value contains transport text absent from the payload file. [Codex output-limit documentation](https://learn.chatgpt.com/docs/hooks#large-hook-output)

   Replace with:

   > “Inspect the recorded model-visible context and compare it with the launcher’s expected complete emitted value, including header and footer. A spill file is diagnostic evidence, not proof of full delivery. If the runtime exposes no suitable record, mark direct delivery verification unverified rather than passing it from raw output or spill-file contents.”
