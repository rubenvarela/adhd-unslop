   142	## Lifecycle
   143	
   144	Activation. The skill is active when the user invokes it (`/adhd-unslop` in
   145	Claude Code, `$adhd-unslop` in Codex) or when the always-on hook injects it
   146	at session `startup` or `clear`. Explicit user invocation enables both
   147	modes. Hook delivery initializes mode defaults only after a complete
   148	matching bundle is available; an incomplete bundle initializes neither
   149	mode. Receiving a complete bundle preserves known mode states; an unknown
   150	mode defaults to active. Claude Code blocks
   151	model-initiated Skill calls (`disable-model-invocation: true`). Codex
   152	disables implicit skill selection (`allow_implicit_invocation: false`). The
   153	Codex AGENTS.md fallback explicitly tells the model to read and follow the
   154	complete installed SKILL.md.
   155	
   156	Two modes, ADHD and unslop, each with an independent switch. ("Mode" is
   157	one of the two rule sets. "Chunk" is one of the three hook deliveries.)
   158	Each mode holds its own state for the session:
   159	
   160	- "stop adhd mode" disables ADHD and leaves unslop's current state unchanged.
   161	- "stop unslop" disables unslop and leaves ADHD's current state unchanged.
   162	- "normal mode" disables both.
   163	- Invoking the skill again enables both.
   164	- Confirm each change in one line naming what is now active.
   165	
   166	State rule, in the skill and in every chunk header: restore the latest
   167	known state of each mode in this session. Explicit invocation enables both.
   168	Stop commands change only the named mode. Receiving or reloading these
   169	instructions does not change known state. After a complete bundle is
   170	available, each unknown mode defaults to active. A newly completed bundle
   171	with a different hash (an upgrade mid-session) replaces the rules without
   172	resetting mode states. Repeated chunks from an older bundle do not select
   173	that bundle again. Quoted or discussed control phrases are not commands.
   174	
   175	Persistence. Active parts stay active for the rest of the session, across
   176	topic changes. The hook also fires on `resume` and `compact` to restore the
   177	instructions after context loss.
   178	
   179	Known limitation, documented in README. Mode state lives in conversation
   180	context, not durable storage. Compaction or resume can lose it. Reinjection
   181	restores instructions, not lost state, so it may restore the active
   182	defaults and a stop command may need repeating. A file-backed state store
   183	is not built in v1.

   267	### Hook (both runtimes)
   268	
   269	Codex supports plugin `hooks/hooks.json` with `SessionStart` sources
   270	`startup|resume|clear|compact`, sets `PLUGIN_ROOT` and `CLAUDE_PLUGIN_ROOT`,
   271	and requires the user to review and trust the current hook definition in
   272	`/hooks`; a changed definition needs review again because trust is recorded
   273	against the definition's hash (developers.openai.com/codex/hooks). The
   274	upstream i-have-adhd launcher already reads both env vars, so one
   275	`hooks.json` serves both runtimes.
   276	
   277	Output caps. Claude Code caps each returned hook context value at 10,000
   278	characters and replaces larger values with a file path and preview
   279	(code.claude.com/docs/en/hooks). Codex caps each handler at about 2,500
   280	tokens by default and raises it per handler with `additionalContextLimit`.
   281	The build reports the exact emitted size of every chunk; the current
   282	overlay plus stripped upstream bodies already exceed 19,000 characters, so a
   283	single handler cannot deliver the composite on Claude Code.
   284	
   285	Delivery model. Matching handlers run concurrently. All three are
   286	synchronous. Each successful handler contributes its own context value
   287	subject to its own limit. Nothing depends on arrival order or on transcript
   288	message boundaries. One matcher group is not an all-or-nothing contract:
   289	Codex can skip untrusted handlers and disable individual ones, and a timeout
   290	or crash can drop any chunk. Completeness is therefore a model instruction
   291	carried in every chunk, not a runtime guarantee.
   292	
   293	Design: three command handlers under one `SessionStart` matcher group. Each
   294	runs the same launcher with `ADHD_UNSLOP_CHUNK` set to `1`, `2`, or `3`.
   295	The payloads are contiguous slices of the generated composite, in order:
   296	
   297	1. Composite prefix through the end of the lifecycle section.
   298	2. The i-have-adhd block, including its provenance markers.
   299	3. The unslop block, including its markers, and the final check.
   300	
   301	Concatenating the three payloads in index order reproduces the composite
   302	body byte-for-byte. Transport text (header and footer) is separate from the
   303	payload.
   304	
   305	Generated chunk files. `tools/build.mjs` writes `hooks/chunks/1.md`,
   306	`2.md`, `3.md` and `hooks/chunks/manifest.json`. The launcher
   307	reads the manifest, validates the selected payload's hash, assembles the
   308	complete value (header, payload, footer, expanded flag paths), checks it
   309	against the size limits, and only then writes stdout. Tests reconstruct
   310	the composite from the payloads and reject stale generated files.
   311	
   312	The manifest records SHA-256 over the exact UTF-8 bytes of the composite
   313	body and of each payload, plus each payload's byte count and UTF-16 code
   314	unit count. Payload whitespace and line endings are not normalized.
   315	Environment-dependent emitted sizes are not committed; the launcher
   316	measures the complete expanded value at runtime.
   317	
   318	Chunk header (identical wording in every chunk, with N and HASH filled in):
   319	
   320	```
   321	ADHD-UNSLOP INSTRUCTIONS. Chunk N of 3 from bundle HASH. Apply this bundle
   322	only once all three chunks with this hash have arrived. If any is missing,
   323	retain the previously selected complete bundle and the current mode
   324	states, say once which chunk is missing, and do not activate from the
   325	partial set. A repeated chunk with the same hash and index is a repeat,
   326	not a new activation. Do not combine chunks from different hashes. A newly
   327	completed bundle replaces its rules without resetting mode states; repeated
   328	chunks from an older bundle do not select that bundle again. Receiving
   329	instructions does not change established mode state: restore the latest
   330	known state of the ADHD mode and the unslop mode in this session; after a
   331	complete bundle is available, default each unknown mode to active.
   332	Precedence: on a direct reply ADHD wins a conflict, elsewhere unslop wins.
   333	```
   334	
   335	Chunk footer:
   336	
   337	```
   338	END adhd-unslop chunk N of 3 (HASH). To stop always-on injection remove
   339	every opt-in flag: <expanded flag paths>. "normal mode" turns both modes
   340	off for this session.
   341	```
   342	
   343	Missing or untrusted handlers are not recovered by another route. README
   344	tells the user to trust or enable all three handlers, or to invoke the
   345	skill explicitly instead.
   346	
   347	Opt-in flags. The launcher checks for `.adhd-unslop-always` under
   348	`CLAUDE_CONFIG_DIR` (default `~/.claude`) and under `CODEX_HOME` (default
   349	`~/.codex`). Either flag enables all three handlers in either runtime. With
   350	neither flag present, exit 0 without output. With a flag present, emit only
   351	the selected chunk, after validation.
   352	
   353	Failure reporting. With opt-in present, a missing chunk file, invalid
   354	manifest, hash mismatch, or oversized value returns one bounded JSON
   355	`systemMessage` naming the failed chunk and the reason, then exits 0. It
   356	returns no `additionalContext` and no payload. Both runtimes show
   357	`systemMessage` to the user without adding it to instruction context. With
   358	no opt-in, the launcher stays silent.
   359	
   360	Token estimate. One shared function in `hooks/lib.mjs`, `ceil(utf16 code
   361	units / 4)`, is used by the build, the launcher, and the tests.
   362	
   363	Codex fallback without hooks: README gives a `~/.codex/AGENTS.md` snippet
   364	that instructs the model to read and follow the complete installed
   365	`SKILL.md` for `adhd-unslop` at the start of every session. The snippet
   366	contains no rules of its own.
   367	
   368	Codex prompt stub (`.codex-plugin/prompts/adhd-unslop.md`) is an optional
   369	slash shortcut. Not shipped in v1; README notes how to add one. Claude Code
   370	users can also type the qualified `/adhd-unslop:adhd-unslop` if another

   373	### Upgrade flow
   374	
   375	```
   376	node tools/sync.mjs --check                     # upstream/ matches pinned sha256
   377	node tools/sync.mjs --bump i-have-adhd <commit> # fetch at commit, stage, print diff
   378	node tools/build.mjs                            # regenerate composite, stamp versions

   382	
   383	`--bump` fetches SKILL.md and LICENSE from raw.githubusercontent.com at the
   384	commit into a staging directory (`.sync-staging/<name>/`), records a
   385	separate sha256 for each file, builds and tests against the staged pins,
   386	and only then promotes sources, pins, and generated output together. On
   387	failure it keeps staging for inspection and leaves canonical files
   388	unchanged. It warns when the new body adds a rule number or heading the
   389	overlay does not cite, and fails when the overlay cites a rule number that
   390	no longer exists or when the new body references a runtime dependency
   391	(`references/`, `scripts/`, `agents/`, or a relative link) that the
   392	composite does not ship.

    80	
    81	Apply rules only from active parts, subject to each part's own conditions
    82	and exceptions. A conflict exists when satisfying one applicable
    83	instruction would violate another. When both parts apply and conflict, ADHD
    84	wins for a direct reply and unslop wins for other writing. Compatible
    85	instructions stay in force everywhere. Example: ADHD says nothing about em
    86	dashes or the word `delve`, so unslop rules 13 and 7 apply to replies too.
    87	These scope, lifecycle, and precedence instructions govern any conflicting
    88	statement inside the embedded upstream bodies.

    90	### Surfaces, classified per passage
    91	
    92	Direct reply. Text that talks to the current user about their request in
    93	this conversation. Answers, progress reports, tool-call announcements the
    94	runtime requires, clarifying questions, status restatements, task or plan
    95	tool entries the user reads, a command or snippet offered as the user's next
    96	step, and the agent's own proposed next steps shown for approval before

   142	## Lifecycle
   143	
   144	Activation. The skill is active when the user invokes it (`/adhd-unslop` in
   145	Claude Code, `$adhd-unslop` in Codex) or when the always-on hook injects it
   146	at session `startup` or `clear`. Explicit user invocation enables both
   147	modes. Hook delivery initializes mode defaults only after a complete
   148	matching bundle is available; an incomplete bundle initializes neither
   149	mode. Receiving a complete bundle preserves known mode states; an unknown
   150	mode defaults to active. Claude Code blocks
   151	model-initiated Skill calls (`disable-model-invocation: true`). Codex
   152	disables implicit skill selection (`allow_implicit_invocation: false`). The
   153	Codex AGENTS.md fallback explicitly tells the model to read and follow the
   154	complete installed SKILL.md.
   155	
   156	Two modes, ADHD and unslop, each with an independent switch. ("Mode" is
   157	one of the two rule sets. "Chunk" is one of the three hook deliveries.)
   158	Each mode holds its own state for the session:
   159	
   160	- "stop adhd mode" disables ADHD and leaves unslop's current state unchanged.
   161	- "stop unslop" disables unslop and leaves ADHD's current state unchanged.
   162	- "normal mode" disables both.
   163	- Invoking the skill again enables both.
   164	- Confirm each change in one line naming what is now active.
   165	
   166	State rule, in the skill and in every chunk header: restore the latest
   167	known state of each mode in this session. Explicit invocation enables both.
   168	Stop commands change only the named mode. Receiving or reloading these
   169	instructions does not change known state. After a complete bundle is
   170	available, each unknown mode defaults to active. A newly completed bundle
   171	with a different hash (an upgrade mid-session) replaces the rules without
   172	resetting mode states. Repeated chunks from an older bundle do not select
   173	that bundle again. Quoted or discussed control phrases are not commands.
   174	
   175	Persistence. Active parts stay active for the rest of the session, across
   176	topic changes. The hook also fires on `resume` and `compact` to restore the
   177	instructions after context loss.
   178	
   179	Known limitation, documented in README. Mode state lives in conversation
   180	context, not durable storage. Compaction or resume can lose it. Reinjection
   181	restores instructions, not lost state, so it may restore the active
   182	defaults and a stop command may need repeating. A file-backed state store
   183	is not built in v1.

   267	### Hook (both runtimes)
   268	
   269	Codex supports plugin `hooks/hooks.json` with `SessionStart` sources
   270	`startup|resume|clear|compact`, sets `PLUGIN_ROOT` and `CLAUDE_PLUGIN_ROOT`,
   271	and requires the user to review and trust the current hook definition in
   272	`/hooks`; a changed definition needs review again because trust is recorded
   273	against the definition's hash (developers.openai.com/codex/hooks). The
   274	upstream i-have-adhd launcher already reads both env vars, so one
   275	`hooks.json` serves both runtimes.
   276	
   277	Output caps. Claude Code caps each returned hook context value at 10,000
   278	characters and replaces larger values with a file path and preview
   279	(code.claude.com/docs/en/hooks). Codex caps each handler at about 2,500
   280	tokens by default and raises it per handler with `additionalContextLimit`.
   281	The build reports the exact emitted size of every chunk; the current
   282	overlay plus stripped upstream bodies already exceed 19,000 characters, so a
   283	single handler cannot deliver the composite on Claude Code.
   284	
   285	Delivery model. Matching handlers run concurrently. All three are
   286	synchronous. Each successful handler contributes its own context value
   287	subject to its own limit. Nothing depends on arrival order or on transcript
   288	message boundaries. One matcher group is not an all-or-nothing contract:
   289	Codex can skip untrusted handlers and disable individual ones, and a timeout
   290	or crash can drop any chunk. Completeness is therefore a model instruction
   291	carried in every chunk, not a runtime guarantee.
   292	
   293	Design: three command handlers under one `SessionStart` matcher group. Each
   294	runs the same launcher with `ADHD_UNSLOP_CHUNK` set to `1`, `2`, or `3`.
   295	The payloads are contiguous slices of the generated composite, in order:
   296	
   297	1. Composite prefix through the end of the lifecycle section.
   298	2. The i-have-adhd block, including its provenance markers.
   299	3. The unslop block, including its markers, and the final check.
   300	
   301	Concatenating the three payloads in index order reproduces the composite
   302	body byte-for-byte. Transport text (header and footer) is separate from the
   303	payload.
   304	
   305	Generated chunk files. `tools/build.mjs` writes `hooks/chunks/1.md`,
   306	`2.md`, `3.md` and `hooks/chunks/manifest.json`. The launcher
   307	reads the manifest, validates the selected payload's hash, assembles the
   308	complete value (header, payload, footer, expanded flag paths), checks it
   309	against the size limits, and only then writes stdout. Tests reconstruct
   310	the composite from the payloads and reject stale generated files.
   311	
   312	The manifest records SHA-256 over the exact UTF-8 bytes of the composite
   313	body and of each payload, plus each payload's byte count and UTF-16 code
   314	unit count. Payload whitespace and line endings are not normalized.
   315	Environment-dependent emitted sizes are not committed; the launcher
   316	measures the complete expanded value at runtime.
   317	
   318	Chunk header (identical wording in every chunk, with N and HASH filled in):
   319	
   320	```

   322	only once all three chunks with this hash have arrived. If any is missing,
   323	retain the previously selected complete bundle and the current mode
   324	states, say once which chunk is missing, and do not activate from the
   325	partial set. A repeated chunk with the same hash and index is a repeat,
   326	not a new activation. Do not combine chunks from different hashes. A newly
   327	completed bundle replaces its rules without resetting mode states; repeated
   328	chunks from an older bundle do not select that bundle again. Receiving
   329	instructions does not change established mode state: restore the latest

   373	### Upgrade flow
   374	
   375	```
   376	node tools/sync.mjs --check                     # upstream/ matches pinned sha256
   377	node tools/sync.mjs --bump i-have-adhd <commit> # fetch at commit, stage, print diff
   378	node tools/build.mjs                            # regenerate composite, stamp versions
   379	node --test tests/                              # invariants
   380	git diff upstream/ skills/ overlay/             # review every change for applicability, conflicts, activation, dependencies
   381	```
   382	
   383	`--bump` fetches SKILL.md and LICENSE from raw.githubusercontent.com at the
   384	commit into a staging directory (`.sync-staging/<name>/`), records a
   385	separate sha256 for each file, builds and tests against the staged pins,
   386	and only then promotes sources, pins, and generated output together. On
   387	failure it keeps staging for inspection and leaves canonical files
   388	unchanged. It warns when the new body adds a rule number or heading the
   389	overlay does not cite, and fails when the overlay cites a rule number that
   390	no longer exists or when the new body references a runtime dependency
   391	(`references/`, `scripts/`, `agents/`, or a relative link) that the
   392	composite does not ship.

   395	
   396	1. Composite equals fresh `build.mjs` output.
   397	2. Each upstream body appears byte-for-byte between its markers; nothing
   398	   else sits between the marker pairs.

   400	4. Authored overlay prose passes mechanical unslop checks: no em dash, no

   402	   vocabulary, no title case headings, no decorative emoji. Fenced blocks,

   406	   per interaction in a shared `tests/interactions.json`.
   407	6. Overlay carries the unslop "always apply" mandate and all three switches.
   408	7. Hook: silent without flag; with the Claude flag or the Codex flag, each
   409	   chunk's emitted value is header plus payload plus footer, and after
   410	   removing header and footer the payloads concatenated in index order
   411	   reproduce the composite body byte-for-byte; every header carries the
   412	   index, total, bundle hash, completeness rule, state rule, and precedence
   413	   line; exits 0 with empty stdout when no flag is present; with a flag
   414	   present and a missing chunk file, missing manifest, hash mismatch,

   416	   JSON object with a `systemMessage` and no `additionalContext`; works with
